# Day 12 - Salesforce DX Workflow

## What is Salesforce DX?

Salesforce DX (Developer Experience) is a modern development approach that helps developers build, test, and deploy Salesforce applications using source-driven development.

Benefits:
- Better project organization
- Easy integration with GitHub
- Faster deployments
- Improved team collaboration
- Easier testing and maintenance

## Why CLI Matters

Salesforce CLI allows developers to perform Salesforce operations using commands instead of browser clicks.

Benefits:
- Faster deployment
- Easier automation
- Metadata retrieval
- Running tests
- Managing multiple orgs

CLI improves productivity and reduces manual work.

## Why GitHub Matters

GitHub is used to store and manage project source code.

Benefits:
- Version control
- Collaboration
- Backup of project files
- Change tracking
- Easy rollback

GitHub acts as the source of truth for enterprise projects.

# Core Tasks

## Task-1: Developer Workflow Thinking

### Why do professional developers use GitHub, CLI, and DX instead of only browser clicks?

Professional developers use GitHub, CLI, and Salesforce DX because large projects require proper tracking, testing, deployment, and collaboration.

### GitHub
- Stores project source code
- Tracks every change
- Maintains version history
- Supports team collaboration
- Allows rollback when problems occur

### CLI
- Automates repetitive tasks
- Speeds up deployments
- Runs tests efficiently
- Reduces manual effort

### Salesforce DX
- Supports source-driven development
- Improves project organization
- Integrates with GitHub
- Simplifies deployments

These tools make development faster, safer, and easier to manage compared to only using browser clicks.


## Task-2: Team Collaboration Thinking

### Suppose 10 developers work on the same Salesforce project.

### Problems Without Version Control

- Developers can overwrite each other's work
- No history of changes
- Difficult bug tracking
- Risk of losing important work

### Problems Without Branches

- Features interfere with each other
- Increased conflicts
- Difficult testing process
- Unfinished work affects others

### Problems Without Deployment Workflow

- Missing components during deployment
- Environment inconsistencies
- Production failures
- Difficult rollback process

Version control, branching, and deployment workflows help teams work efficiently and avoid these issues.

## Task-3: Real Engineering Thinking

### College Coding Assignments vs Enterprise Software Development

| College Assignments | Enterprise Software Development |
|--------------------|--------------------------------|
| Individual work | Team collaboration |
| Small projects | Large systems |
| Limited testing | Extensive testing |
| Local execution | Multi-environment deployment |
| Simple submissions | Structured releases |
| No rollback process | Rollback mechanisms |

### Testing

**College Assignments**
- Basic functionality testing

**Enterprise Software**
- Unit Testing
- Integration Testing
- Regression Testing
- User Acceptance Testing

### Collaboration

**College**
- Mostly individual work

**Enterprise**
- Team collaboration
- Code reviews
- Shared repositories

### Deployment

**College**
- Run locally

**Enterprise**
- Sandbox deployment
- Staging deployment
- Production deployment

### Rollback

Enterprise systems require rollback mechanisms to recover quickly from deployment failures.

### Reliability

Enterprise software must remain stable because many users depend on it daily.
